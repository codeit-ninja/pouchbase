Plugins can declare `categories`, and the registry API filters by category. The manifest can leave out `name`, `version`, `license` and other fields that `package.json` has, takes a `$schema` for editor completion (`pouchbase-plugin schema` prints it), and the server module adds `createOidcProvider`, `fetchJson`, `defineField` and `defineAuthProvider`. `pouchbase-plugin init` offers `field`, `page`, `auth-provider` and `empty` templates, `pouchbase-plugin add` adds a field, page or auth provider with its files, `dev` serves every build as `<version>-dev.<n>` (unless `--exact-version`), and `validate` checks the server code's handlers against the manifest. UI files may import the dashboard's components from `@pouchbasejs/ui` (`HOST_MODULES`), auth providers can have an SVG `icon` from `ui/` (provider ids follow the exported `PROVIDER_ID_PATTERN`), and bundles may hold `.svg` files. The docs describe how hosts run server code (in its own Worker on your Cloudflare account) and that `*.example.com` in `permissions.network` matches subdomains, not `example.com` itself. Provider ids `password`, `email` and `otp` are reserved (`RESERVED_PROVIDER_IDS`), and bundles whose server code still imports other modules are refused (`serverCodeIssues`).
