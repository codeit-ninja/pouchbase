New collections start without fields: add an **ID** field with the generator of your choice (auto-increment, UUID v4, UUID v7 or a random string) and **Created** and **Updated** timestamp fields only when you need them. Existing collections keep their `id`, `created_at` and `updated_at`, which are now regular fields that can be renamed, reordered and deleted (built-in collections keep theirs). Without an ID field, records are identified by their row number and relation fields can't point to the collection. Date fields accept `@now` as default value: the time the record is created. A default value can also be a **SQL expression** with SQLite's date, time, text, math and JSON functions, such as `datetime('now', '+7 days')` or `lower(hex(randomblob(4)))`, evaluated when a record is created. Expressions are written in an editor with autocomplete for every allowed function (with its signature and a description), keywords, and the time values and modifiers of the date functions. Fields can be changed after they are created: **Edit settings** in the edit collection sheet changes the default value, list items, accepted file types and size, rich text format, id generator and whether a relation or list allows multiple values, keeping the records' data. Field names no longer reserve `id`.
